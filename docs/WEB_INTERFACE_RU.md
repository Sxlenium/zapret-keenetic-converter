# Импорт результата через веб-интерфейс nfqws2 на Keenetic

Инструкция составлена для интерфейса `nfqws-keenetic-web` с разделами
**Настройки**, **Списки**, **Логи** и **Скрипты**. Проверенная компоновка
интерфейса: web `3.0.23`, nfqws2 `1.2.4`. В других версиях подписи могут
немного отличаться, но назначение файлов остаётся тем же.

## Самый важный ответ

После конвертации не вставляйте Windows-файл `.bat` и не вставляйте весь
результат в поле **Пользовательская стратегия**.

Для установки только через веб-интерфейс используйте содержимое каталога:

```text
converted/<имя-профиля>/web-import/
├── nfqws2.conf
├── README.md
└── lists/
    └── *.list
```

- файлы из `web-import/lists/` создаются во вкладке **Списки**;
- весь файл `web-import/nfqws2.conf` вставляется во вкладку
  **Настройки → nfqws2.conf**;
- каталог `blobs/` загружать не нужно: в веб-варианте бинарные шаблоны уже
  встроены в конфиг в поддерживаемом nfqws2 hex-формате;
- обычный `converted/<имя-профиля>/nfqws2.conf` предназначен прежде всего для
  установки по SCP вместе с каталогами `lists/` и `blobs/`.

## 1. Что должно быть установлено заранее

До импорта должны работать:

1. Entware на накопителе Keenetic;
2. актуальный `nfqws2-keenetic`;
3. `nfqws-keenetic-web`;
4. компоненты Netfilter, необходимые выбранной версии пакета;
5. доступ к веб-интерфейсу nfqws2, обычно по адресу вида
   `http://192.168.1.1:90/`.

Если штатная конфигурация nfqws2 не запускается, сначала исправьте установку
пакета. Конвертированный профиль не исправляет отсутствующие модули ядра,
неверно установленный Entware или неисправный накопитель.

## 2. Создание результата конвертации

Пример для PowerShell:

```powershell
py -3 -m zapret_keenetic `
  "C:\Tools\zapret-discord-youtube" `
  "general (ALT11).bat" `
  --output ".\converted\alt11-keenetic" `
  --target keenetic `
  --interface eth3
```

Каталог после выполнения содержит два варианта установки:

```text
alt11-keenetic/
├── nfqws2.conf          # вариант для SCP
├── lists/               # вариант для SCP
├── blobs/               # вариант для SCP
├── web-import/          # вариант для веб-интерфейса
├── REPORT.md
└── report.json
```

Не смешивайте варианты. Если вставляете `web-import/nfqws2.conf`, используйте
списки из `web-import/lists/`. Если копируете обычный `nfqws2.conf` по SCP,
копируйте обычные `lists/` и `blobs/`.

## 3. Проверка отчёта до изменения роутера

Откройте `REPORT.md` и проверьте:

- нет ли предупреждений `WARNING`;
- совпадает ли выбранный `.bat`-профиль;
- указан ли реальный WAN-интерфейс;
- присутствуют ли нужные TCP- и UDP-порты;
- сколько профилей прочитано и записано.

Особенно важна строка `ISP_INTERFACE` в `web-import/nfqws2.conf`. Значения
`eth3`, `eth2.2` и `ppp0` являются только примерами. Неверный интерфейс часто
даёт ситуацию «служба работает, но трафик не изменился».

Проверить маршрут через SSH можно командой:

```sh
ip route get 192.0.2.1
```

Имя после `dev` обычно и есть требуемый интерфейс. Для PPPoE, нескольких
провайдеров, туннеля или политики маршрутизации результат проверяйте именно в
рабочем режиме подключения.

## 4. Обязательная резервная копия

### Вариант без SSH

1. Откройте **Настройки → nfqws2.conf**.
2. Щёлкните внутри редактора.
3. Нажмите `Ctrl+A`, затем `Ctrl+C`.
4. Вставьте текст в локальный файл, например `nfqws2-before-import.conf`.
5. Убедитесь, что локальный файл не пуст и начинается с текущих переменных
   конфигурации.

Вкладка `nfqws2.conf-opkg` может содержать вариант, установленный пакетом, но
не следует считать её гарантированной копией последней рабочей пользовательской
конфигурации.

### Более надёжный вариант через SSH

```sh
stamp=$(date +%Y%m%d-%H%M%S)
cp -p /opt/etc/nfqws2/nfqws2.conf "/opt/etc/nfqws2/nfqws2.conf.$stamp.bak"
```

Не публикуйте пароль веб-интерфейса и SSH в отчётах об ошибках, скриншотах и
файлах репозитория.

## 5. Загрузка списков через вкладку «Списки»

Сначала откройте на компьютере папку `web-import/lists/`.

Для каждого файла `имя.list` выполните:

1. В веб-интерфейсе откройте **Списки**.
2. Если вкладка с точно таким именем уже существует, откройте её. Если нет,
   нажмите **Создать новый файл**.
3. В поле **Имя файла** введите имя без окончания `.list`.
   Для `list-general.list` вводится `list-general`.
4. Создайте файл и откройте появившийся редактор.
5. На компьютере откройте одноимённый файл как обычный текст в UTF-8.
6. Скопируйте только его содержимое. Не копируйте имя файла, Markdown-разметку
   или тройные обратные кавычки.
7. В редакторе списка нажмите `Ctrl+A` и вставьте содержимое.
8. Нажмите **Сохранить**.
9. Перейдите на другую вкладку и обратно, чтобы убедиться, что текст сохранился.

Повторите действия для всех файлов, перечисленных также в
`web-import/README.md`.

### Важно про имена списков

Веб-интерфейс сам добавляет `.list`. Не вводите `list-general.list`, если окно
прямо показывает, что расширение будет добавлено автоматически: иначе может
получиться имя `list-general.list.list`.

Не заменяйте автоматически штатные `user.list`, `exclude.list`, `auto.list`,
`ipset.list` и `ipset_exclude.list`, если их имена не указаны в созданном
`web-import/nfqws2.conf`. Конвертер обычно использует отдельные имена, чтобы не
уничтожать пользовательские данные.

Пустой файл списка допустим, если `REPORT.md` пометил его как необязательный
пользовательский список (`INFO / empty-user-list`). Создать его всё равно нужно,
поскольку путь присутствует в конфиге.

## 6. Вставка полного конфига

После загрузки всех списков:

1. Откройте локальный файл `web-import/nfqws2.conf` в текстовом редакторе.
2. Нажмите `Ctrl+A`, затем `Ctrl+C`.
3. В веб-интерфейсе откройте **Настройки**.
4. Выберите именно внутреннюю вкладку **nfqws2.conf**, а не **Конфиг** и не
   `nfqws2.conf-opkg`.
5. Щёлкните внутри большого редактора исходного текста.
6. Нажмите `Ctrl+A`. Весь старый конфиг должен быть выделен внутри редактора,
   а не вся веб-страница.
7. Вставьте новый текст сочетанием `Ctrl+V`.
8. Проверьте начало и конец файла. В начале должны быть комментарий
   `Generated by zapret-keenetic-converter` и `ISP_INTERFACE`, в конце —
   `NFQUEUE_NUM`, `USER` и `CONFIG_VERSION`.
9. Нажмите зелёную кнопку **Проверить домены**, если она доступна. Она проверяет
   доменные записи, но не заменяет проверку всего синтаксиса и запуск службы.
10. Нажмите **Сохранить** один раз и дождитесь завершения операции.

Не обновляйте страницу и не закрывайте вкладку, пока сохранение не завершилось.
Не нажимайте **Сохранить** повторно много раз.

## 7. Почему нельзя вставлять всё в «Пользовательскую стратегию»

Экран **Настройки → Конфиг** разбивает файл на отдельные переменные:

| Поле интерфейса | Переменная в файле |
|---|---|
| Сетевой интерфейс | `ISP_INTERFACE` |
| Параметры запуска | `NFQWS_BASE_ARGS` |
| Базовая стратегия | `NFQWS_ARGS` |
| Стратегия QUIC | `NFQWS_ARGS_QUIC` |
| Стратегия UDP | `NFQWS_ARGS_UDP` |
| Пользовательская стратегия | `NFQWS_ARGS_CUSTOM` |
| Параметры IPSET | `NFQWS_ARGS_IPSET` |
| Режим работы | `NFQWS_EXTRA_ARGS` |
| TCP-порты | `TCP_PORTS` |
| UDP-порты | `UDP_PORTS` |
| Название политики | `POLICY_NAME` |
| Исключать политику | `POLICY_EXCLUDE` |
| IPv6 | `IPV6_ENABLED` |

Конвертер специально размещает независимые профили по нескольким переменным и
сохраняет разделители `--new`. Если весь файл вставить в одно поле, оболочка
передаст строки присваивания как аргументы nfqws2, и служба не запустится.

Теоретически значения можно разнести по форме вручную. Практически это не
рекомендуется: легко потерять кавычки, пустые переменные, переносы строк или
границу профилей. Импорт через редактор полного `nfqws2.conf` точнее.

## 8. Проверка после сохранения

### В веб-интерфейсе

1. Откройте **Логи**.
2. Обновите журнал, если он не обновился автоматически.
3. Ищите сообщения о запуске nfqws2 и загрузке профилей.
4. Ошибок `unknown option`, `file not found`, `cannot open`, `invalid config`
   или постоянного цикла перезапуска быть не должно.

Если веб-интерфейс сохранил файл, но служба не перезапустилась, выполните по SSH:

```sh
service nfqws2-keenetic restart
service nfqws2-keenetic status
```

Дополнительные проверки:

```sh
ps | grep '[n]fqws2'
iptables-save | grep nfqws
logread | grep -i nfqws
```

При включённом IPv6:

```sh
ip6tables-save | grep nfqws
```

### На клиентском устройстве

1. Полностью остановите локальный Flowseal/zapret, VPN и похожие программы.
2. Убедитесь, что устройство использует проверяемый Keenetic, а не мобильную
   сеть или другой шлюз.
3. Закройте и заново откройте браузер и Discord, чтобы старые соединения не
   искажали результат.
4. Проверьте открытие YouTube, запуск и перемотку нескольких видео.
5. Проверьте Discord в браузере, приложение, голосовой канал и демонстрацию
   экрана.
6. Если настроена политика Keenetic, убедитесь, что тестовое устройство входит
   в неё или исключено из неё в соответствии с `POLICY_EXCLUDE`.

## 9. Если список слишком большой для браузера

Крупные `ipset` и hostlist могут медленно вставляться в редактор или превысить
возможности браузера. Тогда используйте гибридный способ:

1. Обычные каталоги `lists/` и `blobs/` скопируйте по SCP в
   `/opt/etc/nfqws2/`.
2. Во вкладку **Настройки → nfqws2.conf** вставьте обычный файл
   `converted/<имя-профиля>/nfqws2.conf`, не файл из `web-import/`.
3. Перезапустите и проверьте службу.

Нельзя использовать обычный конфиг с одними только веб-списками: в нём другие
имена файлов и внешние пути к `blobs/`.

## 10. Откат через веб-интерфейс

Если после импорта служба не запускается:

1. Откройте **Настройки → nfqws2.conf**.
2. Замените весь текст содержимым сохранённого
   `nfqws2-before-import.conf`.
3. Нажмите **Сохранить**.
4. При необходимости перезапустите службу через SSH.
5. Проверьте **Логи**.

Ранее созданные дополнительные `.list` можно оставить: неиспользуемые файлы не
влияют на работу. Удаляйте их только после успешного отката и только если точно
знаете, что старый конфиг на них не ссылается.

Откат по SSH из резервной копии:

```sh
cp -f /opt/etc/nfqws2/nfqws2.conf.<дата>.bak /opt/etc/nfqws2/nfqws2.conf
service nfqws2-keenetic restart
```

## 11. Частые ошибки

### Кнопка «Сохранить» неактивна

Редактор не зарегистрировал изменение. Щёлкните внутри него, внесите и отмените
один символ либо повторно вставьте текст. Перед сохранением ещё раз проверьте,
что конфиг не пуст.

### `file not found` для `.list`

Имя во вкладке **Списки** не совпадает с путём в `web-import/nfqws2.conf`.
Проверьте регистр, дефисы и отсутствие двойного `.list.list`.

### `file not found` для `/blobs/`

Скорее всего, в веб-интерфейс вставлен обычный `nfqws2.conf`, а не
`web-import/nfqws2.conf`. В веб-варианте не должно быть ссылок на каталог
`/blobs/`; объявления начинаются с `--blob=...:0x...`.

### Конфиг сохранился, но сайты не работают

Проверьте по порядку:

1. `ISP_INTERFACE`;
2. статус процесса nfqws2;
3. правила `iptables`/`ip6tables`;
4. TCP- и UDP-порты;
5. политику доступа Keenetic;
6. наличие всех списков;
7. предупреждения в `REPORT.md`;
8. тест без локального Zapret/VPN;
9. другую стратегию Flowseal — одна стратегия не обязана работать у всех
   провайдеров.

### После сохранения пропали собственные настройки

Импорт полного файла заменяет текущий `nfqws2.conf` целиком. Верните резервную
копию и либо повторно конвертируйте с нужными параметрами, либо вручную перенесите
только осознанно выбранные настройки. Не объединяйте два конфига простым
добавлением одного в конец другого.

## 12. Обновление профиля

При обновлении Flowseal:

1. создайте новый пустой выходной каталог;
2. повторите конвертацию;
3. прочитайте новый `REPORT.md`;
4. сделайте новую резервную копию роутера;
5. заново загрузите все списки из нового `web-import/lists/`;
6. только после этого замените `nfqws2.conf`;
7. проверьте логи и клиентские устройства;
8. храните последний рабочий конфиг до завершения проверки.

Конвертация переносит синтаксис стратегии, но не гарантирует, что профиль,
работающий через WinDivert на одном Windows-компьютере, будет одинаково работать
через NFQUEUE на каждом роутере и у каждого провайдера.
