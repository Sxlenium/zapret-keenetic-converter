# Проверка 0.4.0rc2 с Flowseal 1.10.3

Цель: Keenetic Giga KN-1012, KeeneticOS 5.1.3, nfqws2-keenetic 1.2.8,
web 3.0.23. Пакет использует zapret2 v1.0.5.2. Это тестовая сборка:
локальные проверки не подтверждают эффективность у конкретного провайдера.

## Исправления

- ALT13/ALT3: altorder=1 сохраняет порядок «до хоста, fake хоста, после хоста,
  настоящий хост» и не добавляет второй fake. Поддерживается midhost.
- Fake fooling (`ts`, `badseq`, `md5sig`, `badsum`) не применяется к полезным
  сегментам multisplit/multidisorder. Параметры fake-пакетов сохраняются.
- Для multidisorder используется штатный multidisorder_legacy.
- Дополнительная Lua-функция встроена в конфиг; штатные Lua-файлы менять не нужно.
  Hex-кодировка в lua-init нужна для передачи одного аргумента через init-скрипт.
  Разбор/компиляция выполняются при старте, а не на каждом пакете.
- Точный режим установки выбран по умолчанию; гибридный доступен отдельно.

## Первый тест: исходная ALT13

1. Сохраните текущий nfqws2.conf и списки через web-интерфейс. Автоустановщик
   также делает резервную копию и пытается откатить изменения при ошибке запуска.
2. В конвертере выберите каталог Flowseal 1.10.3 и `general (ALT13).bat`.
3. Перенесите текущие ISP_INTERFACE, POLICY_NAME и POLICY_EXCLUDE из рабочего
   конфига. Не выбирайте WAN-интерфейс по модели роутера: он зависит от подключения.
4. Для первого теста: Game Filter выключен, TLS clone выключен, лимит повторов 0,
   строгий режим включён, режим установки **Точный**.
5. Для ручного web-импорта используйте `web-import/nfqws2.conf` и все `.list`
   из `web-import/lists/`. Полный конфиг вставляется в редактор nfqws2.conf,
   а не в поле пользовательской стратегии. Пароль вводите только локально.
6. Перезапустите службу. Проверьте её статус и отсутствие Lua/runtime errors
   в логах. Запуск службы сам по себе не доказывает работу стратегии.
7. На одном и том же клиенте выключите локальный zapret/VPN. Убедитесь, что
   клиент входит в нужную политику. Проверьте YouTube (запуск, перемотка,
   стабильное воспроизведение 5 минут) и Discord (вход, голос 5 минут, медиа).

Запишите до/после: скорость загрузки, время первого открытия, буферизацию,
задержку голоса, CPU и память роутера во время нагрузки. Используйте одинаковые
клиент, подключение и сервисы. Если связь ухудшилась, восстановите сохранённый
конфиг и списки, затем перезапустите службу.

## Отдельные эксперименты

Меняйте по одному параметру после базового теста:

1. **TLS clone** (`--tls-fake-mode clone`). Все TLS fake данного профиля заменяются
   одной копией текущего ClientHello с рандомизацией и дублированием session ID.
   Если клонирование не удалось, fake пропускается. Исходные TLS mods заменяются
   на rnd,rndsni,dupsid. Это не точный эквивалент Flowseal и не обещание ускорения:
   клонирование требует CPU. HTTP, QUIC, seqovl и unknown могут продолжать
   использовать бинарные шаблоны исходной стратегии.
2. **Лимит повторов** (`--fake-repeats-limit 3`, например). Уменьшает только
   существующие значения repeats выше лимита, не увеличивает меньшие значения
   и не меняет число полезных сегментов. Снижает число отправляемых fake-пакетов,
   но может ухудшить обход DPI. Рабочий предел определяется измерением.

В REPORT.md и report.json экспериментальные изменения отмечены отдельно.
Гибридный режим смешивает выбранные правила со штатной стратегией; для сравнения
ALT13 используйте точный режим. Успех blockcheck на Windows не гарантирует тот же
результат при NFQUEUE, другом MTU или offloading на роутере.

## Проверки разработчика

`python -m pip install -e ".[test]"`, затем `python -m unittest discover -v`.
Пакетная проверка без запуска BAT: `python -m scripts.check_flowseal ПАПКА_FLOWSEAL --json report.json`.
Проверяются все стратегии, оба target, четыре режима Game Filter и исходный/экспериментальный режимы.
Lua проверяется в тестовом runtime Lupa: порядок payload/offset, fooling только
fake, midhost, повторные фрагменты, ошибки отправки и отсутствие хоста.
Это модель отправки пакетов, не проверка сетевого стека MIPS/ARM.
